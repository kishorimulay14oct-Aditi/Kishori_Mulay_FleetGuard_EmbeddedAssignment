# FleetGuard Hardware Pin Mapping

## 1. Purpose

This document defines the proposed ESP32 GPIO assignments for the
FleetGuard environmental monitoring prototype.

The pin mapping provides connections for the SHT31 temperature/humidity
sensor, OLED display, RGB/status LED, buzzer, optional door sensor, and
serial debugging.

The assignments are prototype-level engineering decisions and shall be
verified against the final ESP32 development board and selected
peripherals before hardware fabrication.

---

## 2. Proposed Pin Assignment

| Function | Peripheral | ESP32 Pin | Interface | Direction |
|---|---|---|---|---|
| Temperature/Humidity SDA | SHT31 Environmental Sensor | GPIO 21 | I2C | Bidirectional |
| Temperature/Humidity SCL | SHT31 Environmental Sensor | GPIO 22 | I2C | Bidirectional |
| OLED SDA | OLED Display | GPIO 21 | I2C | Bidirectional |
| OLED SCL | OLED Display | GPIO 22 | I2C | Bidirectional |
| RGB LED Red | RGB LED | GPIO 25 | GPIO/PWM | Output |
| RGB LED Green | RGB LED | GPIO 26 | GPIO/PWM | Output |
| RGB LED Blue | RGB LED | GPIO 27 | GPIO/PWM | Output |
| Buzzer | Buzzer | GPIO 14 | GPIO/PWM | Output |
| Door Status | Door Sensor | GPIO 33 | Digital GPIO | Input |
| UART TX | Debug Interface | GPIO 17 | UART | Output |
| UART RX | Debug Interface | GPIO 16 | UART | Input |

## 3. Temperature and Humidity Sensor

The selected temperature and humidity sensor is an SHT31 digital
environmental sensor using the I2C interface.

```text
SHT31                ESP32

SDA  --------------- GPIO 21
SCL  --------------- GPIO 22
VCC  --------------- 3.3 V
GND  --------------- GND

The SHT31 and OLED display share the same I2C bus.

Proposed SHT31 I2C address:

0x44

The sensor provides digital temperature and relative humidity
measurements to the ESP32.

The final sensor address and electrical connections shall be verified
against the selected hardware before production deployment.

4. OLED Display

The OLED display uses the ESP32 I2C interface.

OLED                ESP32

SDA  -------------- GPIO 21
SCL  -------------- GPIO 22
VCC  -------------- 3.3 V
GND  -------------- GND

Proposed OLED I2C address:

0x3C

The OLED shares the I2C bus with the SHT31 sensor.

Both devices can share the same I2C bus because they use different
addresses.

The I2C bus allows multiple compatible peripherals to communicate using
the same SDA and SCL signal lines.

5. I2C Bus Configuration

The proposed I2C bus is:

                    ESP32
                      |
             +--------+--------+
             |                 |
          GPIO 21           GPIO 22
             |                 |
            SDA               SCL
             |                 |
        +----+----+       +----+----+
        |         |       |         |
      SHT31      OLED    SHT31     OLED
      0x44       0x3C    0x44      0x3C
I2C Assignment
SDA = GPIO 21
SCL = GPIO 22

SHT31 = 0x44
OLED  = 0x3C

The final I2C addresses shall be verified against the selected
components before hardware fabrication.

Appropriate I2C pull-up resistors shall be provided if they are not
already included on the selected sensor or display modules.

6. RGB LED

The RGB LED uses three GPIO/PWM outputs.

ESP32                 RGB LED

GPIO 25  ------------ RED
GPIO 26  ------------ GREEN
GPIO 27  ------------ BLUE
GND      ------------ GND

Current-limiting resistors shall be used with the LED channels as
required by the selected LED and circuit configuration.

Proposed Status Indication
GREEN  → NORMAL
YELLOW → WARNING
RED    → CRITICAL

Yellow can be generated by activating the red and green channels
together.

The exact LED logic depends on whether a common-anode or common-cathode
RGB LED is selected.

7. Buzzer

The buzzer is connected to a GPIO capable of generating the required
alert signal.

ESP32                 Buzzer

GPIO 14  ------------ Buzzer Signal
GND      ------------ GND

The buzzer is used for local audible alerts during:

WARNING
CRITICAL
Sensor failure

For a buzzer requiring more current than an ESP32 GPIO can safely
provide, an appropriate transistor or driver circuit shall be used.

The final buzzer driver circuit shall be verified before production
hardware implementation.

8. Optional Door Sensor

A digital door-status sensor may be connected to GPIO 33.

Door Sensor           ESP32

Signal  ------------- GPIO 33
GND     ------------- GND

The sensor may provide:

DOOR CLOSED
DOOR OPEN

Door events can be passed to the Event Logger.

The door sensor is optional for the initial environmental monitoring
prototype and may be included in a future system revision.

9. UART Debug Interface

UART is retained for firmware debugging and serial logging.

ESP32                 USB/UART Debug Interface

GPIO 17  ------------ RX
GPIO 16  ------------ TX
GND      ------------ GND

The UART interface may be used during development to observe:

Sensor readings
Condition state
Threshold transitions
Sensor errors
System restart events
Configuration information
Debug messages

UART is intended primarily for development and diagnostic purposes.

10. Power Connections

The ESP32 and peripherals shall be powered from an appropriate
regulated supply.

Conceptually:

             +------------------+
             | Regulated Power  |
             |     Supply       |
             +--------+---------+
                      |
                      v
                +-----------+
                |   ESP32   |
                +-----+-----+
                      |
          +-----------+-----------+
          |           |           |
          v           v           v
       SHT31        OLED      LED/Buzzer

All components shall have a common ground reference.

The actual power supply voltage shall be verified against the selected
components before assembly.

The ESP32 and connected peripherals shall not be supplied beyond their
specified voltage limits.

12. Pin Selection Considerations

The proposed GPIO assignments were selected to keep the prototype
simple and modular.

The following considerations shall be checked before final hardware
implementation:

ESP32 development-board pin availability
Boot-strapping pin restrictions
GPIO input/output capability
PWM capability for LED and buzzer control
I2C availability
UART availability
Peripheral voltage levels
Pull-up and pull-down requirements
Electrical loading
Interrupt requirements
External driver requirements
Power supply requirements

The final pin assignment shall be verified against the exact ESP32
board variant being used.

13. Interface Summary

The proposed prototype uses:

I2C
 ├── SHT31 Temperature/Humidity Sensor
 └── OLED Display

GPIO
 ├── RGB LED
 ├── Buzzer
 └── Optional Door Sensor

UART
 └── Debugging / Serial Logging

Wi-Fi
 └── Future MQTT Connectivity

This interface allocation provides sufficient connectivity for the
initial FleetGuard prototype while keeping additional GPIO and
communication options available for future expansion.

14. Engineering Notes

The pin mapping represents a prototype-level design.

Before production deployment, the following shall be verified:

Exact ESP32 development board pin availability.
SHT31 and OLED I2C addresses.
I2C pull-up requirements.
GPIO electrical limits.
RGB LED current requirements.
Buzzer current requirements and driver circuit.
Door sensor electrical interface.
Power supply voltage and current capacity.
Grounding and noise considerations.
EMC/EMI requirements for the final application.

The engineering values and pin assignments in this document are
intended for proof-of-concept development and must be validated before
production hardware implementation.
