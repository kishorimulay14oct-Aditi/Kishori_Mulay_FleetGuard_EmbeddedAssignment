# FleetGuard Hardware Pin Mapping

## 1. Purpose

This document defines the proposed ESP32 GPIO assignments for the
FleetGuard environmental monitoring prototype.

The pin mapping provides connections for the temperature/humidity
sensor, OLED display, RGB/status LED, buzzer, optional door sensor,
and serial debugging.

The assignments are prototype-level engineering decisions and shall be
verified against the final ESP32 development board and selected
peripherals before hardware fabrication.

---

## 2. Proposed Pin Assignment

| Function | Peripheral | ESP32 Pin | Interface | Direction |
|---|---|---:|---|---|
| Temperature/Humidity Data | Environmental Sensor | GPIO 4 | Digital | Input |
| OLED SDA | OLED Display | GPIO 21 | I2C | Bidirectional |
| OLED SCL | OLED Display | GPIO 22 | I2C | Bidirectional |
| RGB LED Red | RGB LED | GPIO 25 | GPIO/PWM | Output |
| RGB LED Green | RGB LED | GPIO 26 | GPIO/PWM | Output |
| RGB LED Blue | RGB LED | GPIO 27 | GPIO/PWM | Output |
| Buzzer | Buzzer | GPIO 14 | GPIO/PWM | Output |
| Door Status | Door Sensor | GPIO 33 | Digital GPIO | Input |
| UART TX | Debug Interface | GPIO 17 | UART | Output |
| UART RX | Debug Interface | GPIO 16 | UART | Input |

---

## 3. Temperature and Humidity Sensor

Proposed connection:

```text
Temperature/Humidity Sensor
          |
          | DATA
          v
       GPIO 4
          |
          v
        ESP32

The sensor data line is connected to GPIO 4.

The final GPIO assignment depends on the specific sensor selected.

If an I2C-based temperature/humidity sensor is selected instead, the
sensor may share the I2C bus with the OLED display.

4. OLED Display

The OLED uses the ESP32 I2C interface.

OLED                ESP32

SDA  -------------- GPIO 21
SCL  -------------- GPIO 22
VCC  -------------- 3.3 V
GND  -------------- GND

The I2C bus allows the OLED to communicate using only two signal lines.

Other compatible I2C peripherals may share the same bus provided that
their addresses do not conflict.

5. RGB LED

The RGB LED uses three GPIO/PWM outputs.

ESP32                 RGB LED

GPIO 25  ------------ RED
GPIO 26  ------------ GREEN
GPIO 27  ------------ BLUE
GND      ------------ GND

Current-limiting resistors shall be used with the LED channels where
required by the selected LED and circuit configuration.

Proposed status indication:

GREEN  → NORMAL
YELLOW → WARNING
RED    → CRITICAL

Yellow can be generated by activating the red and green channels
together.

6. Buzzer

The buzzer is connected to a GPIO capable of generating the required
alert signal.

ESP32                 Buzzer

GPIO 14  ------------ Buzzer Signal
GND      ------------ GND

For a buzzer requiring more current than an ESP32 GPIO can safely
provide, an appropriate transistor or driver circuit shall be used.

7. Optional Door Sensor

A digital door-status sensor may be connected to GPIO 33.

Door Sensor           ESP32

Signal  ------------- GPIO 33
GND     ------------- GND

The sensor may provide:

DOOR CLOSED
DOOR OPEN

Door events can be passed to the Event Logger.

8. UART Debug Interface

UART is retained for firmware debugging and serial logging.

ESP32                 USB/UART Debug Interface

GPIO 17  ------------ RX
GPIO 16  ------------ TX
GND      ------------ GND

The UART interface may be used during development to observe:

Sensor readings
Condition state
Threshold transitions
Sensor errors
System restart events
Configuration information
Debug messages
9. Power Connections

The ESP32 and peripherals shall be powered from an appropriate
regulated supply.

Conceptually:

             +------------------+
             | Regulated Power  |
             |     Supply       |
             +--------+---------+
                      |
                      v
                +-----------+
                |   ESP32   |
                +-----+-----+
                      |
          +-----------+-----------+
          |           |           |
          v           v           v
       Sensor       OLED      LED/Buzzer

All components shall have a common ground reference.

The actual power supply voltage shall be verified against the selected
components before assembly.

11. Pin Selection Considerations

The proposed GPIO assignments were selected to keep the prototype
simple and modular.

The following considerations shall be checked before final hardware
implementation:

ESP32 development-board pin availability
Boot-strapping pin restrictions
GPIO input/output capability
ADC requirements if analog sensors are used
PWM capability for LED and buzzer control
I2C availability
UART availability
Peripheral voltage levels
Pull-up and pull-down requirements
Electrical loading
Interrupt requirements

The final pin assignment shall be verified against the exact ESP32
board variant being used.

12. Interface Summary

The proposed prototype uses:

I2C
 ├── OLED Display
 └── Future I2C Sensor / Peripheral

GPIO
 ├── Temperature/Humidity Sensor
 ├── RGB LED
 ├── Buzzer
 └── Door Sensor

UART
 └── Debugging / Serial Logging

Wi-Fi
 └── Future MQTT Connectivity

This interface allocation provides sufficient connectivity for the
initial FleetGuard prototype while keeping additional GPIO and
communication options available for future expansion.
